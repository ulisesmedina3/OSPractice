Ball & Tube Simulator — Operating Systems Project

1. Project Overview

This project simulates a ball floating inside a vertical tube, controlled by a fan at the bottom.

The objective is to develop a multithreaded C program that controls the fan speed to maintain the ball at a desired height.

The project consists of two programs:

* ball_simulator.py — Python program responsible for the graphical interface, ball physics, and updating the ball’s position.
* controller.c — C program responsible for reading the ball’s height, receiving user input, and controlling the fan speed.

Both programs communicate through POSIX shared memory.

2. How the System Works

The Python simulator calculates the movement of the ball using gravity and the upward force generated by the fan.

The C controller reads the current ball height and compares it with the desired reference height.

It then calculates the fan speed necessary to move the ball toward the reference.

The process repeats approximately every 100 milliseconds.

Shared Memory

Both programs access the same POSIX shared memory object:

/ball_control

The shared memory contains three floating-point values occupying 12 bytes:

Variable	Bytes	Description
height	0–3	Current ball height, written by Python
speed	4–7	Fan speed between 0.0 and 1.0, written by C
reference	8–11	Desired ball height, written by C

The Python simulator continuously reads the fan speed and updates the ball’s height.

The C controller reads the height and adjusts the fan speed.

3. Multithreading Architecture

The C controller uses two POSIX threads.

Thread 1 — User Input

Allows the user to enter a new desired reference height through the terminal.

For example:

Enter reference height (0-50): 30

The controller updates the reference height in shared memory.

Thread 2 — Control Loop

Executes periodically, approximately every 100 milliseconds.

It performs the following operations:

1. Reads the current ball height.
2. Reads the desired reference height.
3. Calculates the error between the reference and actual height.
4. Calculates the new fan speed.
5. Limits the fan speed to the range 0.0–1.0.
6. Writes the new fan speed into shared memory.

Timer and Signals

The controller uses:

* setitimer() to generate a periodic timer.
* SIGALRM to signal each timer expiration.
* pthread_sigmask() to control which thread receives the signal.
* sigaction() to register the signal handler.
* A semaphore to notify the control thread when a timer tick occurs.

The main thread blocks SIGALRM before creating the two threads.

Both threads inherit this blocked signal mask.

The control thread then unblocks SIGALRM, allowing it to receive timer signals while the user-input thread remains protected.

4. Control Algorithm

The controller uses a proportional control algorithm:

error = reference - height;
speed = bias + Kp * error;

Where:

* error is the difference between the desired and current height.
* Kp determines how strongly the fan responds to the error.
* bias provides enough fan power to approximately balance gravity.

The simulator uses:

gravity = -25.0
lift = fan_v * 35.0

Therefore, the approximate fan speed needed to balance gravity is:

bias = 25 / 35 = 0.714

The example controller uses:

Kp = 0.04;

The final fan speed is limited to the range 0.0–1.0.

5. Requirements

The project is designed for a Linux environment.

Required software:

* Python 3
* Tkinter
* posix_ipc
* GCC
* POSIX Threads
* POSIX shared memory support

Install dependencies in Ubuntu / GitHub Codespaces

sudo apt-get update
sudo apt-get install -y python3-tk gcc xvfb
python3 -m pip install posix_ipc

If Python reports an externally managed environment, use a virtual environment:

python3 -m venv .venv
source .venv/bin/activate
pip install posix_ipc

6. Compile the C Controller

Open a terminal in the project directory.

Compile the C program:

gcc controller.c -o controller -pthread -lrt

This creates an executable named controller.

The -pthread option enables POSIX thread support.

On modern Linux systems, -lrt is often unnecessary.

7. Running the Project

Both programs must run in the same Linux environment because they communicate through POSIX shared memory.

Step 1 — Start the Python Simulator

Open Terminal 1:

python3 ball_simulator.py

The simulator creates the /ball_control shared memory object.

Important: Start the simulator before the C controller.

Step 2 — Start the C Controller

Open Terminal 2:

./controller

The controller connects to the existing shared memory object and starts its threads.

Step 3 — Change the Reference Height

In the controller terminal, enter a reference height:

Enter reference height (0-50): 30

The controller updates the reference height and adjusts the fan speed.

The ball should move toward the new target.

8. Running in GitHub Codespaces

GitHub Codespaces normally does not provide a graphical desktop display.

Running:

python3 ball_simulator.py

may produce:

_tkinter.TclError: no display name and no $DISPLAY environment variable

This happens because Tkinter requires a graphical display.

Run with a Virtual Display

Install Xvfb:

sudo apt-get install -y xvfb

Then start the simulator:

xvfb-run -a python3 ball_simulator.py

The simulator will execute using a virtual display.

However, the graphical window will not be visible in the Codespaces browser.

You can still run the C controller in another terminal and inspect its output.

To view the actual graphical simulator through Codespaces, a VNC/noVNC setup or another browser-accessible display is required.

9. Testing Shared Memory

After starting the Python simulator, verify that the shared memory object exists:

ls -l /dev/shm/ball_control

The object should occupy 12 bytes.

You can also inspect the three floats using Python:

python3 -c "import struct; print(struct.unpack('3f', open('/dev/shm/ball_control', 'rb').read(12)))"

Example output:

(10.0, 0.714, 25.0)

The values represent:

(current_height, fan_speed, reference_height)

The actual values will change while the simulation is running.

10. Common Problems

Error: No Display Name

_tkinter.TclError: no display name and no $DISPLAY environment variable

Cause: Tkinter cannot find a graphical display.

Solution: Run the simulator in a graphical Linux session or use Xvfb.

Error: No Module Named posix_ipc

Cause: The Python dependency is missing.

Solution:

python3 -m pip install posix_ipc

Error: shm_open: No such file or directory

Cause: The Python simulator has not created the shared memory object yet.

Solution: Start the Python simulator before running the controller.

Controller Does Not Update the Ball

Check that:

* Both programs are running in the same Linux environment.
* The shared memory name is /ball_control.
* The shared memory structure contains three 4-byte floats in the correct order.
* The control thread is receiving SIGALRM.
* The timer interval is configured to 100,000 microseconds.
* The fan speed is clamped between 0.0 and 1.0.

11. Important Operating Systems Concepts

Concept	Function or mechanism
Interprocess communication	POSIX shared memory
Shared memory creation/opening	shm_open()
Memory mapping	mmap()
Thread creation	pthread_create()
Thread synchronization	pthread_join()
Periodic timer	setitimer()
Signal handling	sigaction()
Thread signal masking	pthread_sigmask()
Timer notification	sem_post() and sem_wait()

12. Summary

The Ball & Tube Simulator demonstrates how multiple operating system mechanisms work together.

Python simulates the physical system and provides the graphical interface.

The C controller uses POSIX shared memory to exchange information with Python, Pthreads to execute input and control tasks concurrently, and a periodic timer with signals to schedule control updates.

The main objective is to keep the ball near a desired reference height by adjusting fan speed based on the difference between the actual and desired positions.

Note: The controller is an educational example. It does not guarantee hard real-time execution or completely synchronized cross-process shared-memory access.
